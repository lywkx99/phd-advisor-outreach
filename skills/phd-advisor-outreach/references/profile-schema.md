# 档案结构

申请者档案是整个流程的事实来源。筛选的参数、邮件里关于申请者的每一句话，都从这里取。空白档案见 [profile-template.md](../assets/profile-template.md)，建工作文件夹时会复制到 `申博资料/02_档案/申请者档案.md`，在那里填写。

## 一、三层信息

| 层 | 内容 | 怎么得到 |
|---|---|---|
| A 事实 | 身份、时间线、硬指标、成果、工作取材卡、技能、现有材料、联系历史 | 主要从材料读，读不出的再问 |
| B 意愿 | 动机、方向、导师偏好、院校与地域、现实约束、风险偏好、沟通风格 | 只能通过访谈问出来 |
| C 专家结论 | 资本评估、定位、筛选参数、邮件参数、方向桥接表、决定与取舍记录、补课清单 | 你来产出，用户确认后生效 |

## 二、来源标签

每条信息后面标来源。

| 标签 | 含义 | 能不能写进邮件 |
|---|---|---|
| `[材料]` | 来自简历、论文、投稿系统、成绩单等文件 | 能 |
| `[口述]` | 用户亲口确认，没有文件佐证 | 能，但涉及论文状态等可查证的内容时提醒用户核对 |
| `[推断-待确认]` | 你从材料里推出来的硬事实，或你拟的写法，用户还没确认 | 确认后才能 |
| `[假设]` | 用户没有表态，你给的默认值 | 只用于筛选参数，交付时要说明 |

带日期的信息写上日期，尤其是论文状态和联系记录。

为什么分这么细：标签主要管硬事实。论文状态、署名、数据、学历这类查得到的内容，不能由你推出来就写进邮件，必须有材料或用户亲口确认。技能和能力怎么表述属于弹性项，由你往足里拟、当面告诉用户，他认可后就可以用，并在“决定与取舍记录”里留一笔。要挡住的只有一种情况：把完全没碰过、只在研究计划里“打算做”的东西，写成已经做过。

## 三、字段

### A 层

**身份与时间线**：姓名；本科院校、专业、毕业年份；硕士院校、专业、学位类型（学术型或专业型）、导师；预计毕业时间及是否确定；目标入学年；电话、微信、邮箱及哪些写进落款。

**硬指标**：英语成绩（类型、分数、日期）；成绩或排名；主要奖项。

**成果清单**：每项一行，包括题目、作者顺序与本人位置、期刊或去向、状态、状态证据与日期、DOI、可核实的期刊信息及来源。状态只用这些词：已发表、已接收、修回中、同行评审中、编辑处理中、已投稿、在写、设想。

**工作取材卡**：每项主要工作一张。

| 栏 | 内容 |
|---|---|
| 科学问题 | 这项工作要解决什么 |
| 本人做了什么 | 按动作写：想法、设计、实验、分析、写作，各是谁 |
| 关键证据 | 支持主要结论的数据是什么 |
| 亮点 | 这项工作最值得讲的一点，用户自己的话 |
| 可以写到什么程度 | 能力和角色往足里写的说法，用户认可的版本 |
| 红线 | 这项工作里不能写的：没做过的实验、没得到的结果、没有证据的结论。只列真正过线的，不要把所有有分量的说法都划进来 |
| 要补什么 | 追问阶梯里答不上来的地方，同步进补课清单 |

“可以写到什么程度”和“红线”要一起填。前者保证写足，后者保证不过线。

**技能三档**：

- 扎实：自己做过，原理和细节都讲得清。
- 用过：自己做过或用过，但原理或细节现在讲不透。
- 只了解：学过、读过、看别人做过，没有动过手。

前两档都作为已有技能写进邮件，可以用“掌握”“能够独立完成”这样的说法；第二档的每一项同时记入补课清单。第三档里，用户愿意学、面试前又补得上的，可以写“学习过”“了解其原理”；其余的放进“希望学习”。没有动过手的不写成做过。

**拟开展**：博士阶段想做、现在还没做的内容。和已有成果分开记，防止混写。

**现有材料**：简历、工作介绍、研究计划、推荐人，各自的路径、版本日期。研究计划如果是为某位导师定制的，标明对象，避免发错。

**联系历史**：不写在档案里，写在单独的联系账本中，见 [运行与数据](operation.md)。

### B 层

**动机与出路**：读博的原因；毕业后的去向；今年没申上的打算。

**方向**：这一项不是让用户自己填的，由你从材料和引导式提问里提炼，讲给用户听，一起定下来。做法见 [引导式访谈](interview-guide.md) 的方向一轮。记录这几样：

- 提炼依据：几项工作里一直没变的那条线，以及用户说的兴趣点和遗憾。
- 最贴合的方向：一句话，落在“解决什么问题”这一层，带上对象作锚点。它是邮件的主线，也是筛选的中心。模板里对应“核心方向”这一项。
- 子方向：最贴合方向之下三到五个更具体的方向，每个记已有的基础、还要补什么、贴合程度。用来对每位导师定制方向短语，也用作“按特定方向”筛选的口径。
- 宽泛的大方向：所属的一两个大领域。导师不够时往外放宽用。
- 相邻可以接受的方向、明确不做的方向。
- 每一项都配中英文关键词，并注明用户确认的日期。

提炼完要用一条专门的“方向总结”回复告诉用户，不夹在别的内容里。

**导师偏好**：大组或小组；是否要求导师亲自指导；对管理风格的偏好；对一作机会的重视程度；排序题的结果（最看重的三项、可以放弃的一项）。

**院校与平台**：层级底线；是否接受科研院所；是否接受联合培养；是否在意学位授予单位。

**地域**：硬约束（不去的地方及原因）；偏好（想去的地方）。

**现实约束**：经济；家庭；最晚何时需要结果；能否接受空档；现导师是否知情和支持；保底方案。

**风险偏好**：冲、稳、保的配比；计划联系的数量和开始时间。

**沟通风格**：邮件语气；是否主动提院校背景及怎么提；结尾请求交流的句子怎么措辞（线上汇报、加微信或两者都提；这句话每封必带）；祝福语的习惯；哪些未发表内容不公开；用户指定必须保留的句子。

### C 层

**资本评估**：按 [资本评估](capital-assessment.md) 的格式。

**定位**：冲、稳、保三档的目标画像。

**筛选参数**：关键词矩阵；地域与单位范围；排序权重；排除项；心仪的院校或课题组；已做的筛选轮次（每轮的口径、人数、覆盖范围）。

**邮件参数**：一句话主线；卖点类型；邮件母版的路径和确认日期；披露边界。母版本身是单独的文件 `02_档案/邮件母版.md`，里面有固定段落、核心工作的侧重点清单和经历素材库，设计方法见 [邮件模型](email-model.md)。

**方向桥接表**：按导师的方向类型记：对这类导师，用母版里的哪个侧重点、选素材库里的哪几条、可以探索的环节、要核查的条件和常见错误。它是母版的侧重点清单和素材库的索引。行从方向总结的子方向起步，联系中遇到新的导师类型再加。做法见 [契合度分析](fit-analysis.md)。

**决定与取舍记录**：你替用户做的判断、访谈中出现过的矛盾，各自的处理、理由和用户的回应。用户没有回应的，对应内容标为 `[假设]`。

**补课清单**：已经写进档案或邮件、但用户还讲不透的内容，以及你答应过帮他补的东西。每项记现在的程度、邮件里的写法、面试前要补什么。用户收到面试或交流邀请时，先翻这张表。

## 四、闸门

模板里每个必需字段前有 `〔A〕` 或 `〔B〕` 标记。值是 `【待补】` 就算没填。

| 闸门 | 必需字段 |
|---|---|
| A 可以筛导师 | 目标入学年、预计毕业时间、硕士院校与专业、英语成绩、成果清单、核心方向（即最贴合的方向）、地域硬约束、院校层级底线、联系账本已建立 |
| B 可以写邮件 | A 的全部，加上工作取材卡、技能三档、一句话主线、邮件母版、附件情况、沟通风格、落款信息 |

检查命令：

```text
python scripts/check_profile.py 申请者档案.md
```

脚本只看字段是否填写，并统计 `[假设]` 和 `[推断-待确认]` 的数量。内容是否可信由你判断。没有 Python 时，照上面的表逐项看档案里对应的行是否还是 `【待补】`。

确实没有的内容写“无”，不要留 `【待补】`。比如没有论文，成果清单写“无成文成果”，闸门照样能过，评估时如实处理。

## 五、更新规则

- 新信息逐字段更新，不整份覆盖。旧值有参考意义时保留并注明日期。
- 用户新说的话优先于档案里的旧内容。和材料冲突时，指出冲突，请用户确认。
- 论文状态变了、收到回信、面试了，当天更新。
- 不因为新写了一封邮件，就把账本里“已发送”的状态改回“已起草”。
- 档案里有真实的个人信息。只存在用户指定的位置，不写进 skill 文件夹，不发给无关的服务。
