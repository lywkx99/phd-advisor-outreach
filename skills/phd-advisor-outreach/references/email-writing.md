# 邮件写法

开始前确认档案过了闸门 B。邮件里关于申请者的内容都取自档案：硬事实要有 `[材料]` 或 `[口述]` 的依据，技能和能力用取材卡里用户认可的写法。

邮件分三层：所有用户共用的骨架、为这位用户设计的母版、针对每位导师的五处定制。三层各是什么、母版怎么设计、每位导师改哪里，见 [邮件模型](email-model.md)。本文件讲的是落笔时的规则。

## 一、起草前

写邮件之前，这位导师必须已经做过深查。深查的项目见 [流程地图](workflow.md) 第 4 步，记录用 [核查模板](../assets/advisor-check-template.md)，保存在这位导师的文件夹里。

1. 找用户的邮件母版（`02_档案/邮件母版.md`）。没有就先和用户一起做母版，做法见 [邮件模型](email-model.md) 的“个人母版”。用户急着要这一封时，先写，写完整理成母版初稿。
2. 找这位导师的核查记录。没有，或者只做过初筛，就先做深查。用户直接给主页链接要邮件时也一样，先深查再写，并把他补进名单表。
3. 核查记录超过两三周，或者中间有新情况（简章发布、用户联系了同组的人），把招生情况和查重重新过一遍。
4. 深查的结论是“缓写”或“不写”时，告诉用户原因，由他决定，不硬写。
5. 母版里固定的部分照用；这一封只做五处定制，依据是核查记录。

## 二、各区块落笔的要求

导师通常只花几十秒扫一封陌生邮件。主题和第一段要让他知道三件事：你是谁、做什么方向、想要什么。七个区块里哪些固定、哪些定制，见 [邮件模型](email-model.md)；这里是每个区块写的时候要注意的。

1. **主题**：入学年份、姓名、院校与学位阶段、方向。方向要落到和这位导师相关的具体表述上。
2. **首段**：身份、现导师、预计毕业时间、博士阶段想做的方向，询问目标年份的博士招生计划。
3. **经历段**：只写和这位导师当前问题相关的两三项真实工作，说明做了什么、得到什么能力。不复制整张技能清单。
4. **核心工作段**：事实底稿不变，侧重点随导师方向调整。不为了迎合导师改动事实。
5. **亮点区**：有论文的用成果段，逐条使用档案里确认过的文本，包括题目、作者、期刊、DOI、本人的作者位置和当前状态；已发表、已接收、在审、在写分开写，不合并成一句“发表论文若干篇”。没有论文的用亮点清单，内容和排列按母版。两种都是编号清单，加粗的位置按母版的格式约定。
6. **导师段**：两三句，顺序是“您当前的具体工作，我已有的哪项经验，我希望在您指导下学习或探索哪一环”。不放参考文献、期刊名和年份，不放署名判断。
7. **结尾**：列出附件；再问一次招生；请求线上汇报或加微信的句子（每封必带，这是整封邮件的目的）；母版里定好的院校背景句（如有）；致谢；落款，留电话或微信号。

长度以导师一屏半内读完为准。成果多时成果段可以占较大篇幅，其余段落各自控制在三四句。

格式按母版的约定走：加粗只出现在约定的几处，段落之间空一行。每封邮件的格式都和母版一致，不因为某位导师临时多加粗一句。

## 三、写足，但不过线

这是去保守化在邮件里的落点。检验标准：写上去的每一条，要么现在答得上，要么面试前补得上。规则的来由见 [资本评估](capital-assessment.md)。

**把写小了的写足**

| 缩手缩脚的写法 | 写足的写法 |
|---|---|
| “接触过”“略有了解”“参与了一些” | “掌握”“能够独立完成”“学习并使用过” |
| 只罗列实验名称 | 翻成能力：“能够独立设计并优化某类反应”“具备从设计到表征的完整经验” |
| 主要由自己完成的工作写成“参与” | “主要由我完成”“从选题到论文撰写基本由我独立完成” |
| 在审稿件不提，或一笔带过 | 列进成果段，写明状态，随信附上稿件 |
| 亮点埋在方法细节里 | 每项工作第一句就写最值得讲的一点 |
| “虽然我能力有限”“深知自己不足” | 删掉。不自贬 |
| 用过但讲不透的技能不写 | 写上，同时记入补课清单并告诉用户 |

**不能动的硬事实**

| 过线的写法 | 应该怎么写 |
|---|---|
| “即将发表”“已基本接收” | 写实际状态：同行评审中、修回中 |
| “发表 SCI 论文 3 篇”（其中有在审的） | 逐篇列出状态和本人的作者位置 |
| 共同一作写成唯一一作，二作写成一作 | 按署名原样写 |
| 没做过的实验、没得到的结果写成已完成 | 写进“希望学习”或“拟开展” |
| 完全没碰过的技术写成掌握 | 写“希望在您的指导下学习” |
| 没有检索核实的“首次”“首个” | 直接写做了什么、好在哪里 |
| 只有间接证据却写“证明了某机理” | “结果支持某解释” |

几条补充：

- 技能按档案的三档写：扎实的和用过的都作为已有技能写；只了解的，补得上的写“学习过”，其余放进“希望学习”。
- 起草后对照取材卡：“可以写到什么程度”一栏有没有用足，“红线”一栏有没有碰到。
- 期刊信息写可核实的内容。分区、影响因子对申请者有利时建议写上，要有来源和年份。
- 导师段里对契合度的表达也不必缩着写，但要落在具体的环节上：写“我在某方面的经验可以直接用于您课题组的某项工作”，不写空泛的“高度契合”。
- 关于院校背景：是否提、怎么提，按档案里用户的选择。提的话，限定在“院校背景”，不扩大成“科研能力一般”，并接上一句对自己具体工作的信心。

## 四、语言

- 简洁、具体。对导师谦逊，对自己的工作有信心，两者不矛盾。中英文之间留空格。
- 用“希望在您的指导下学习”，不用“和我的工作相似”“可以合作”这类平起平坐的说法。
- 分清四种内容：我做过的、导师做过的、文献里有先例的、我想学的。
- 未发表的核心想法只写方向，不写实现细节。
- 导师偏好英文或是外籍导师时，用英文写，结构不变。

## 五、交付

1. 收件人信息和简短的查重结论。
2. 完整的主题和正文，可以直接复制。加粗和斜体的位置标清楚，并提醒用户：贴进邮箱后把这些地方设成真正的加粗和斜体，星号不能原样发出去。
3. 正文之外，说明这一封的五处定制各是怎么改的；并把深查的要点重新讲一遍，不要假设用户看过核查记录：选了哪个切入点和理由、契合级别、招生情况、一作观察（两到四句）、少量来源链接、还没核实的事项。
4. 保存路径和实际状态（已起草，未发送）。
5. 我替你定的几件事：这封邮件里你做了哪些判断，比如某项技能按哪种说法写的、选了哪个切入点、哪句话用的是默认设定。逐条说明理由，涉及补课的说明后续安排，最后问是否可以。
6. 需要时加一条建议，比如这位导师和已联系的某位同组、建议先等回复。
7. 下一步：告诉用户这封需要他自己发（或明确授权你发），发之前检查哪几个附件，发完跟你说一声以便记账；然后问是接着写这一批的下一位，还是先停。
8. 介绍回信功能：第一次交付邮件时，专门告诉用户导师可能怎么回、回信贴给你就能帮他判断和起草回复，以及所有往来的共同目标是争取线上展示或加微信。话术见 [回信应对](reply-playbook.md) 的“把这个功能告诉用户”。之后每次交付只带一句提醒。

只改一句话时，只交付改动的部分，不重复整封邮件和整套核查。

## 六、用户自己发送时

邮件默认由用户自己发。第一次交付邮件时，把下面这些讲给他；之后只提醒有变化的。这些是通行的做法，不是规定。

- **用学校邮箱。** 学校邮箱更不容易进垃圾箱，也更可信。发件人的显示名改成真实姓名。
- **先给自己发一封。** 看加粗有没有生效、有没有残留的星号、换行对不对、附件能不能打开。
- **附件用 PDF，文件名带姓名**，总大小不要太大。
- **一封只发一位导师。** 不群发，不密送，不抄送别的老师。
- **同一课题组的老师不同时发。**
- **挑工作日的白天发。** 深夜和节假日发的邮件容易被淹没。
- **发完记一下时间，告诉你。** 你更新联系账本，并把“该跟进的日期”写进待办和日历。
- **过几天看一眼有没有退信。** 邮箱地址过期是常事，退信了就去主页找新地址。

## 七、回信与跟进

导师回信之后的全部做法在 [回信应对](reply-playbook.md) 里：怎么归类、每类意味着什么、回复模板、之后做什么。包括有名额、约交流、婉拒、推荐他人、给指点、折中方案、追问、让走流程、一直没回复、加微信的第一句、交流后的感谢。

两条总的要求：

- 回复同样按母版的语气写，同样遵守“写足但不过线”。回复里不重复自我介绍。
- 每一封回复都服务于同一个目标：争取一次线上展示的机会或加上微信。门开着就明确提，门关了就得体收尾。

**导师邀请交流或面试。** 回复写完就启动 [意向阶段](intent-stage.md)，给五篇核心论文并陪读。面试汇报的 PPT 超出本 skill 的范围，但到了这一步还有三件事要做：提醒用户确认时间和形式、准备工作汇报；请他重读取材卡里“红线”和“要补什么”两栏；翻开档案的补课清单，把答应过的内容逐项兑现，带他把写进邮件但还讲不透的原理过一遍。

用户明确要求发送时才调用邮箱工具，流程见 [查重与核实](verification.md) 的“实际发送”。
