# 查重、事实核实与发送

## 一、查重

先查用户的联系账本，再查已保存的草稿和用户新给的名单。邮箱统一大小写，去掉 Markdown 转义和全角字符。备用邮箱、主页改版、单位调动要人工核实是不是同一个人。

只读辅助脚本：

```text
python scripts/check_duplicates.py --name 姓名 --email 邮箱 --institution 单位 --ledger 联系账本.md --drafts 导师目录
```

`--name`、`--email`、`--table`（xlsx 名单）可以重复。脚本只给出命中的证据和警告，是不是同一个人、有没有发过，由你根据证据判断。

脚本只用 Python 标准库；读 xlsx 需要另装 openpyxl，没装时那张表会被跳过并给出提示。没有 Python 时不用脚本，直接在联系账本、草稿文件夹和名单里搜这位导师的姓名、别名和每一个邮箱，按下表下结论。

| 证据 | 可以下的结论 |
|---|---|
| 用户明确说“已申请”或“已联系” | 记为“用户确认已申请”。不编造发信日期、渠道和内容 |
| 用户明确说“已发送”，或已发送邮件可以核实 | 记为已发送，写上已知的日期、邮箱、主题。不凭空补上回复 |
| 有写给这位导师的草稿，发送没有确认 | “此前已起草，发送状态未确认”。优先在原稿上修改 |
| 只在导师表里有一行 | “此前列入名单，未发现联系证据” |
| 只在另一位导师邮件的参考文献里出现 | 是文献关联，不算联系过。顺便看看两人是不是同一团队 |
| 这一轮检索没有命中 | “现有记录未发现重复”，并说明缺了哪些来源。不能说“确定没发过” |

同名不同邮箱、同邮箱不同姓名，都是需要消歧的线索，不能只凭姓名报重复。

状态词用 [流程地图](workflow.md) “每位导师的状态”里定的那一套，只往前追加。新写的草稿不能把已有的“已发送”降回“已起草”。

## 二、团队关系与导师身份

区分三种关系：现在同一实验室或共同指导、长期合作、师生或校友。用主页、成员介绍、联合培养说明来佐证。共同通讯是继续查的线索，不能据此断言“挂靠招生”“没有独立名额”。

发现用户已联系的导师和新对象属于同一团队时，提醒联系会交叉，给出先后顺序的建议。不替用户决定不写，不替用户撤回，不擅自加抄送。

博导资格、学位授予单位、招生专业、年度名额、实际指导分工，分栏记录。邮件只是询问招生时，不必把所有行政流程查完。

## 三、研究信息的来源

1. 现单位、院系、实验室的官方网页：身份、邮箱、项目、组内学生。
2. 论文原文和补充材料：题目、年份、作者顺序、共同贡献脚注、通讯作者、贡献声明。
3. PubMed、Crossref：发现文献和交叉核对。OpenAlex 这类聚合库只作线索，同名合并和通讯作者字段可能有错。

主页打不开时可以读搜索引擎对该官方页面的索引，按实际读到的精度表述，不说读过全文。查不到的元数据留空或注明未核实。不按拼音猜中文名。

近期在相邻任务里核实过的证据可以复用。岗位、招生、投稿状态这类会变的内容按当天重新判断。区分在线发表年和卷期年。

## 四、一作署名观察

申请者关心入学后能不能拿到一作。这是一个证据有限的初筛，不是对导师的评判。

优先抽查导师独立之后约三篇近期的通讯作者原始研究。样本难找就报告实际数量。有明确疑点或用户要求时再扩大范围。

每篇记录：题目、DOI、年份；是原始研究还是综述；第一作者和共同第一；通讯和共同通讯；导师当时所处的阶段；能核实的作者身份；来源和缺口。

- 名字靠前不证明是学生，排在最后不一定是通讯作者。不只看数据库里的排列。
- 学生身份优先用当时的官方报道或学位信息。毕业博士、博士后、在读博士、硕士分开。
- 导师本人第一兼通讯，需要结合贡献声明理解，不自动等于占了学生的一作。综述、观点文章、博士后阶段延续的成果，和独立后的学生原始研究分开看。
- 不能用别的团队或导师博士后时期的成果，推断新课题组里学生有一作机会。
- 多篇共同通讯说明指导分工值得了解，不能据此认定没人指导。

结论分三类，先写事实再写限定：

| 情况 | 表述 |
|---|---|
| 其他人第一、导师通讯，且有明确的学生实例 | “所查 N 篇原始研究中，导师均为通讯作者，有明确的学生第一或共同第一的实例。未见占用学生一作的明确信号，但不能保证以后的安排。” |
| 独立后有多篇本人第一，分工不明 | “有本人第一兼通讯的记录，需要进一步了解课题分工和署名原则。目前不足以判断存在不当署名。”给出具体例子，不评价人品 |
| 新导师或样本不足 | “材料不足，暂时不能判断学生的一作机会。”列出已知事实和缺口 |

不写“不会抢”“零风险”，不给没有统计依据的概率。简短结论放在邮件正文之外，详细样本随草稿保存。用户只是改字句时，复用已有结论。

## 五、实际发送

只有用户明确授权发送，才进入这一节。写稿、给链接、说“写好了”都不是授权。授权可以来自前文，对象、内容、操作都已明确时不必机械地再问一遍。

1. 用核实过的邮箱对应导师。复查最新的联系和回复，避免同一封重复发送。抄送和密送限于用户授权的范围。
2. 确认最终的主题和正文。删掉查重结论、署名观察、内部笔记和所有占位符。按邮箱支持的格式处理加粗，不要把 Markdown 的星号原样发出去。
3. 核对附件的版本、对象和内容，尤其防止附上为另一位导师写的研究计划。附件缺失时先完成其余工作，再问用户是补上还是省略，不谎称已附。
4. 默认用户没有接入邮箱工具：交付可以直接复制的主题和正文，列出要带的附件，由用户自己发，发完请他告诉你，再更新账本。环境里确实有邮箱工具或用户许可的界面流程时才代发。不去配置凭据。
5. 有成功的响应或能在已发送里查到，才记为已发送。超时或结果不明时先查已发送箱，不盲目重试，避免发两封。仍然不能确认的，记“发送结果待核实”。
6. 联系账本只记必要信息：收件人、主题、日期、发送证据、附件版本。不读取无关的私人邮件。
